# 하이브리드 앱이란

하이브리드 웹앱은 `WebView`로 HTML, CSS, JavaScript를 화면에 그리는 앱입니다. 한 번 만든 웹 코드를 안드로이드와 iOS에서 같이 쓸 수 있다는 장점이 있습니다. 반면 네이티브 앱은 코틀린이나 자바로 플랫폼마다 따로 만들어야 합니다.

보안 관점의 단점은 공격 표면이 늘어난다는 점입니다. 모바일 앱의 약점과 웹의 약점을 둘 다 신경 써야 합니다.

---

# 웹뷰 브릿지

웹뷰 브릿지는 웹 페이지의 JavaScript가 앱의 기능(카메라, 전화 등)을 부를 수 있게 이어 주는 통로입니다. 편리한 만큼, 악의적인 웹 페이지가 이 통로를 부를 수 있으면 위험해집니다.

- `addJavascriptInterface()`: 오래전부터 쓰던 방식이고, 수업에서는 취약한 방식으로 배웠습니다. 어떤 페이지에서 불러도 연결된다는 점이 문제입니다.
- `addWebMessageListener()`: 더 안전한 방식으로 배웠습니다. 요청이 올 수 있는 출처(Origin)를 미리 지정해서 걸러 낼 수 있습니다.

---

# 공격은 어디에서 일어나나

앱 하나에 공격 지점이 세 군데 있다고 정리했습니다.

- 단말기: 악성 스크립트가 든 게시물을 열었을 때 권한이나 로컬 데이터를 빼 가는 경우
- 통신 채널: 중간자 공격으로 패킷을 엿보거나 바꾸는 경우
- 서버: APK를 디컴파일해서 코드 속 API 키를 찾고, 이를 이용해 백엔드에 들어가는 경우

---

# 기억할 점

- 웹뷰를 쓰면 로드할 주소를 검증하고, 브릿지는 꼭 필요한 기능만 연다.
- 코드에 API 키를 넣어 두면 APK를 푸는 순간 노출된다고 생각해야 한다.
- 같은 취약점 유형이라도 앱마다 코드에 나타나는 모양이 다르니, 정적 분석 때 실제 코드를 확인해야 한다. DIVA 분석에서는 `addJavascriptInterface()`가 쓰이지 않았다.
